Cognition: the model adapter

A detailed record of what “cognition” means in this architecture, what we implemented for Chapter 01, how to run it against LM Studio, and what we deliberately deferred (evals, observability, authority).

Chapter 01 complete OpenAI-compatible LM Studio verified
One-liner

Cognition is how the system thinks (LLM + structured skills). The model adapter is the single door to that brain: one factory, OpenAI wire protocol, env-swappable between LM Studio and cloud.

2. Problem we solved

Before Chapter 01, server/src/skills/model.js was Anthropic-only:

  • Required ANTHROPIC_API_KEY
  • No baseURL — could not talk to LM Studio
  • agent-run silently fell back to canned captions when the model failed — looked “alive” when it wasn’t

Goal: one createModel() that speaks the OpenAI-compatible chat API so the same skills work with LM Studio locally and OpenAI (or vLLM) in the cloud by changing env only.

3.2 The factory (behavior)

  • Requires OPENAI_API_KEY and OPENAI_MODEL (clear error if missing)
  • OPENAI_BASE_URL defaults to http://127.0.0.1:1234/v1 (LM Studio)
  • Timeout 60s, maxRetries: 1
  • Skills keep calling createModel().withStructuredOutput(...) — no skill file imports OpenAI/Anthropic directly

3A. Pseudo code

Language-agnostic sketches of what we shipped. Real code lives under server/src/skills/model.js, server/scripts/ping-model.js, and server/src/server.js.

A. Model adapter factory

function createModel(options = {}):
  missing = []
  if env.OPENAI_API_KEY is empty: missing.append("OPENAI_API_KEY")
  if options.model is empty AND env.OPENAI_MODEL is empty:
    missing.append("OPENAI_MODEL")
  if missing is not empty:
    throw Error("Missing required env: " + missing.join(", "))

  return OpenAICompatibleChatClient(
    apiKey     = env.OPENAI_API_KEY,
    model      = options.model OR env.OPENAI_MODEL,
    temperature = options.temperature OR 0.7,
    timeoutMs  = 60_000,
    maxRetries = 1,
    baseURL    = env.OPENAI_BASE_URL OR "http://127.0.0.1:1234/v1"
  )

# Skills NEVER do:
#   import AnthropicSDK
#   import OpenAIVendorSDK
# They only call createModel().

B. Skill using the adapter (structured output)

ContentPlanSchema = {
  hook: string,
  angle: string,
  format: "reel" | "feed" | "carousel",
  ...
}

function planContent(topic, brandGuide?):
  model = createModel().withStructuredOutput(ContentPlanSchema)

  # One LLM call; response must match the schema or the client errors
  result = model.invoke("""
    Plan an Instagram post for topic: {topic}
    Brand guide: {brandGuide}
  """)

  return result   # typed object, not free-form mush

# Pipeline (simplified):
function runContentPipeline(topic):
  plan    = planContent(topic)
  caption = writeCaption(plan.hook, plan.angle, plan.format)
  media   = generateMediaPrompts(plan, caption)
  review  = reviewPost(plan, caption, media)
  return merge(plan, caption, media, review)

C. Ping smoke test

function main():
  loadDotEnv(".env.local")
  print("Pinging model={OPENAI_MODEL} baseURL={OPENAI_BASE_URL}")

  model = createModel()
  reply = model.invoke("Reply with exactly: pong")

  print("ok")
  print("response:", reply.text.trim())
  # success criterion: reply contains "pong"

on error:
  print("ping failed:", error.message)
  exit(1)   # Connection refused ⇒ LM Studio local server not running

D. Agent-run: fail loud vs canned fallback

async function generatePostContent(topic, brand):
  try:
    return runContentPipeline(topic, brand)
  catch error:
    if env.ALLOW_CANNED_FALLBACK == "true":
      log.warn("pipeline failed, using canned fallback", error)
      return cannedDraft(topic)     # demo only
    else:
      throw error                   # default: do not fake success

# HTTP handler
POST /api/posts/:id/agent-run:
  post = db.getPost(id)
  try:
    content = generatePostContent(post.topic, body.brand)
    db.updatePost(id, content, status = "pending_approval")
    return 200 { post, note: "Generated via LangChain skills" }
  catch error:
    log.error("agent-run failed", error)
    return 502 { error: error.message }
    # post is NOT filled with fake hook/caption

createModel():

4. How to run the checkpoint

  1. Open LM Studio; load the model named in OPENAI_MODEL.
  2. Start Local Server (Developer tab) on port 1234.
  3. Confirm the API is up: 
    curl http://127.0.0.1:1234/v1/models
    Connection refused = server not started (the ping script cannot fix that).
  4. Run pnpm --filter server model:ping.
  5. Success we hit: response contains pong.
Checkpoint status

Passed: LM Studio answered pong through createModel(). Cognition door is open.

5. Fail-loud behavior (important)

SituationBehavior
Missing OPENAI_MODEL / key Throw with explicit missing-var message
LM Studio down; ping Connection error, exit code 1
LM Studio down; agent-run HTTP 502 with error message — post not filled with fake copy
ALLOW_CANNED_FALLBACK=true Old demo path: canned hook/caption on pipeline failure

Silent canned success was removed from the default path on purpose: it taught the wrong lesson (“system works”) when cognition was actually offline.

Not as full systems. Chapter 01 only needed a smoke test.

Building a run store or eval harness before a multi-step loop exists creates throwaway scaffolding. See Evals & observability.

7. Four notes (answer key for this layer)

  • What problem does this layer solve? Vendor-agnostic access to a chat model so skills can reason without caring about LM Studio vs cloud.
  • What is allowed to call it? Skills, ping script, and (later) the agent loop — via createModel() only.
  • What must it never do? Side effects (publish, DB policy, OAuth); hide failures behind fake content by default.
  • How do I observe and test it? model:ping; dead-server connection errors; agent-run 502 without fallback.
