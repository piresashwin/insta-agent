Week 3 · Lesson 11

MCP harness

“Any harness” means the same orchestrator tools are reachable from Cursor / Claude Code / scripts via MCP.

Time · 1 day
Learn
  • MCP vs REST: same authority, different clients
  • Tool descriptions are UX for the harness agent
  • Never expose raw publish without the same policy gate
Build
  1. Expand server/src/mcp-server.ts beyond skills (orchestrator + operator tools)
  2. Core: list_posts, get_run, start_run_on_post, get_brand_context
  3. Operator loop: generate_brand_draft → save_brand_profile → generate_visual_identity → fill_week (dry_run default) → commit → optional start_run_on_post
  4. HITL stop: approve / media / publish stay in React — never on MCP
Checkpoint

A run started from MCP shows up in the React monitor with the same run_id. Brand save + dry-run fill_week share SQLite with the dashboard; commit creates draft posts only.

Four notes
  • What problem does this layer solve?
  • What is allowed to call it?
  • What must it never do?
  • How do I observe and test it?
