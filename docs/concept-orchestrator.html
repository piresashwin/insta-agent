Concept · Detailed lesson · Chapter 05

Orchestrator

The agent drafts content. The orchestrator owns durable post state and the only legal paths between statuses. Without this layer, the model (or the UI) invents reality.

Week 2 · Lesson 05 Control plane Built in this repo
One-liner

A post is the product domain object. A run is the flight recorder for one cognition attempt. transitionPost is the single chokepoint for every status write — cognition may patch fields; it may never invent published.

2. Domain entity vs run record

Answers “What is this Instagram draft’s lifecycle?” “What did cognition do this attempt?”

POST /api/posts/:id/agent-run does both: creates a run, fills draft fields from the pipeline, then asks the orchestrator to move the post to pending_approval. Two tables, one HTTP call — orchestrator coordinates.

3. Status machine

draft ──► pending_approval ──► approved
                │     ▲              │
                │     └── changes_requested
                │                    ▼
                └── (self)     media_generating ► media_ready ► …
                regenerate              ▼
                                   published | failed

The self-edge on pending_approval is deliberate: the operator may re-run the agent while still waiting to approve. That is still a legal edge — not a silent SQL overwrite that skips validation.

Terminal-ish states published and failed have empty outgoing lists in the machine for now. Later lessons add retry / reschedule edges when policy and publish are real.

6. Checkpoint (prove the DB never lies)

With the server running (pnpm --filter server dev):

# 1) Create a draft
curl -s -X POST localhost:3001/api/posts \
  -H 'Content-Type: application/json' \
  -d '{"topic":"orch check"}'
# note post.id

# 2) Illegal: skip the machine
curl -s -X POST localhost:3001/api/posts/ID/approve \
  -H 'Content-Type: application/json' \
  -d '{"actor":{"id":"local-dev","name":"Local operator"}}'
# → {"error":"Invalid transition: \"draft\" -> \"approved\". Allowed: [pending_approval]"}

curl -s -X POST localhost:3001/api/posts/ID/published \
  -H 'Content-Type: application/json' -d '{}'
# → Invalid transition draft → published

# 3) Confirm row still draft
curl -s localhost:3001/api/posts/ID
Pass

Illegal transitions return an error body; GET still shows status: "draft". Happy path remains: create → agent-run → pending_approval → approve with actor → approved.

7. Four notes (answered)

  1. Problem? Durable, consistent lifecycle so cognition and clients cannot invent product state.
  2. Who may call it? REST (and later MCP) through the same APIs — React, curl, harnesses. Not the model directly.
  3. Must never? Be the LLM; skip transition checks; let the UI write raw status without validation; let skills set published.
  4. Observe / test? Curl illegal edges; assert status unchanged; after agent-run, inspect post status and linked run_id timeline.
