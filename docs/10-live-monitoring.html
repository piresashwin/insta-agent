Week 3 · Lesson 10

Live monitoring

Observability UX: stream or poll run events into an Activity panel. Correlate post_id ↔ run_id.

Time · 1 day Observability UX
Learn
  • SSE vs polling tradeoffs
  • Rendering tool steps, durations, errors
  • Redacting secrets from event payloads in the UI
Build
  1. GET /api/runs/:id/events (SSE) or poll while running
  2. React Activity panel on post detail
  3. Show model name + step status live
Checkpoint

Start a run; watch steps appear without a full page refresh.

Built in this repo
  • POST /api/posts/:id/agent-run returns 202 + run_id immediately
  • Pipeline appends step events (plan → caption → media → review)
  • GET /api/runs/:id/events?after= — SSE; heartbeat; closes on run_done
  • Agent runs → Activity panel: EventSource + poll fallback; payload redact
Verify 
# After agent-run returns run_id=N:
curl -N localhost:3001/api/runs/N/events
# expect: event: run_meta / run_event / run_done

# UI: New post → Create + run agent → Agent runs tab shows live steps
Four notes
  • What problem does this layer solve?
  • What is allowed to call it?
  • What must it never do?
  • How do I observe and test it?

(1) Watch cognition without guessing. (2) Operators via UI/curl — not the model. (3) Invent run history; show raw secrets. (4) SSE curl or Activity “live” badge.
