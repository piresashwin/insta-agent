Week 4 · Lesson 14

Instagram OAuth

Compliance-sensitive connect flow. Saving App ID ≠ connected. Real consent + token exchange.

Time · 1–2 days Compliance
Learn
  • OAuth consent → short-lived → long-lived token
  • Encrypt secrets at rest; redirect URI hygiene
  • Disconnect / revoke path; log auth events without raw tokens
Build
  1. OAuth initiate + callback endpoints
  2. Encrypt tokens in SQLite
  3. React connection status reflects real Graph auth
Checkpoint

Dashboard shows a real connected Business account; failures are loud, not silently “connected.”

Built in this repo
  • GET /api/auth/instagram/start/:id → Meta consent
  • Provider: Instagram Login (not Facebook Login / Page tokens)
  • Authorize: instagram.com/oauth/authorize
  • Code → api.instagram.com/oauth/access_token → short-lived
  • Short → graph.instagram.com/access_token?grant_type=ig_exchange_token
  • Profile: graph.instagram.com/me; IG user token encrypted at rest
  • POST /api/auth/instagram/:id/token — paste Meta “Generate token” (local, no HTTPS)
  • POST /api/auth/instagram/:id/disconnect; auth_events (no raw tokens)
  • Dev: INSTAGRAM_OAUTH_MOCK=true + Mock connect (optional)
Local connect (no tunnel)
  1. Meta App → Instagram → API setup → Generate token
  2. Accounts → save App ID + secret → Connect with pasted token

Quick Cloudflare/ngrok URLs often fail Meta checks. Browser OAuth needs a stable HTTPS host (PUBLIC_API_BASE / INSTAGRAM_REDIRECT_URI).

Four notes
  • What problem does this layer solve?
  • What is allowed to call it?
  • What must it never do?
  • How do I observe and test it?

(1) Prove a real human consented and we hold a usable Page/IG token. (2) Operator via Accounts UI / OAuth routes — not the agent. (3) Mark connected without Graph; log raw tokens; skip encryption in prod. (4) Happy path → status connected + username; deny/fail → status error + banner.
