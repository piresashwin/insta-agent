Week 2 · Lesson 08

REST interface

Stable HTTP contracts so UI and scripts are interchangeable clients of the orchestrator.

Time · ½–1 day
Learn
  • Errors as contracts (status + body shape)
  • Idempotent reads; careful writes
  • API is not the agent — it starts runs and exposes state
Build
  1. CRUD posts, list/filter, get run timeline
  2. PATCH /api/posts/:id, approve / request-changes
  3. Consistent JSON error shape
Checkpoint

curl alone can create a post, start a run, approve — no UI required.

Built in this repo

GET /api catalog. GET /api/posts?status= filter. PATCH / DELETE /api/posts/:id (no status via PATCH). Errors always { "error": "…" }. Runs: GET /api/runs/:id timeline; ?post_id= on list.

Verify (curl) 
curl -s localhost:3001/api

curl -s -X POST localhost:3001/api/posts \
  -H 'Content-Type: application/json' -d '{"topic":"rest check"}'
# note id

curl -s -X PATCH localhost:3001/api/posts/ID \
  -H 'Content-Type: application/json' -d '{"topic":"rest check patched"}'

curl -s 'localhost:3001/api/posts?status=draft'

# Happy path still: agent-run → approve (needs pending_approval)
curl -s -X POST localhost:3001/api/posts/ID/agent-run \
  -H 'Content-Type: application/json' -d '{}'
curl -s -X POST localhost:3001/api/posts/ID/approve \
  -H 'Content-Type: application/json' \
  -d '{"actor":{"id":"local-dev","name":"Local"}}'

curl -s localhost:3001/api/runs?post_id=ID
