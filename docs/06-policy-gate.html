Week 2 · Lesson 06

Policy gate

Safety core: capability checks before any world mutation. Policy answers “is this (actor, action, resource) allowed?” — not “who is calling?” Status edges stay in Lesson 05; operator auth comes later.

Time · 1 day Critical
Learn
  • Actor + action + resource authorization
  • Allowlists for irreversible actions
  • Deny must be logged for audit
  • How 06 stacks on top of transitionPost (05)
Build
  1. policy.can(actor, action, resource)
  2. Examples: agent may draft / media.search; only human may instagram.publish
  3. World-mutating routes call policy first; deny → policy_deny + needs_human
Checkpoint

Even if the model outputs “publish now”, the tool refuses without approval — and a deny event is stored.

Built in this repo

server/src/policy.ts owns can / assertAllowed / durable policy_deny. server/src/server.ts calls policy before agent-run, approve, request-changes, publish, and published. Checkpoint surface: POST /api/posts/:id/instagram-publish with {"as":"agent"}.

Verify (curl) 
curl -s -X POST localhost:3001/api/posts \
  -H 'Content-Type: application/json' -d '{"topic":"policy check"}'
# use returned id:
curl -s -X POST localhost:3001/api/posts/ID/instagram-publish \
  -H 'Content-Type: application/json' -d '{"as":"agent"}'
# expect: 403 Policy deny … (run_id=N)

curl -s localhost:3001/api/runs/N
# expect: kind "policy", event type "policy_deny", status "needs_human"
