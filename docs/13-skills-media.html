Week 4 · Lesson 13

Skills & media

Expand the skill suite; implement free-media fetch behind policy. Artifacts live on disk + DB.

Time · 1–2 days
Learn
  • Agent loop tools: plan → caption → media_prompts → review → finish
  • media_prompts emits image_prompt (brief) + stock_search_query (Pexels keywords)
  • Human fetch downloads bytes; loop never writes image_url
Build
  1. Wire caption / media-prompt / review into the agent loop
  2. Pexels download via stock_search_query → assets/ → media_ready
  3. Policy: agent may media.search only after human starts; still cannot publish
Checkpoint

After approve → Generate with Pexels, the post has a real image on disk and media_provider=pexels.

Built in this repo
  • POST /agent-run uses runAgent (not fixed pipeline)
  • stock_search_query on the post from media_prompts
  • POST /fetch-media {"provider":"pexels"} — human from approved / regenerate from media_ready
  • UI: Generate with Pexels
  • Key: PEXELS_API_KEY in .env.local
Verify 
# Post must be approved first:
curl -s -X POST localhost:3001/api/posts/ID/fetch-media \
  -H 'Content-Type: application/json' \
  -d '{"provider":"pexels","actor":{"id":"local-dev","name":"Local"}}'
# → status media_ready, image_url …/assets/posts/ID/…

ls server/assets/posts/ID/
