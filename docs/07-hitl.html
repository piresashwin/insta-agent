Week 2 · Lesson 07

HITL approvals

Approval is a state machine, not a prompt. Humans revise with comments; max edits are enforced.

Time · 1 day
Learn
  • Approve vs request-changes vs needs_revision
  • Iteration history as product data
  • When the agent is allowed to re-run
Build
  1. approve / request-changes + iterations rows
  2. Max 3 revisions → needs_revision
  3. Agent re-run only from changes_requested (or explicit restart)
Checkpoint

Full loop in DB: draft → request changes → new run → approve.

Built in this repo

Max MAX_REVISIONS (3) → needs_revision. Agent-run only from draft / changes_requested. POST …/restart → draft. GET …/iterations lists comments.

Verify (curl) 
# After agent-run left status pending_approval:
curl -s -X POST localhost:3001/api/posts/ID/request-changes \
  -H 'Content-Type: application/json' \
  -d '{"author":{"id":"local-dev","name":"Local"},"comment":"sharper hook"}'
# → changes_requested (or needs_revision on 3rd)

curl -s -X POST localhost:3001/api/posts/ID/agent-run -H 'Content-Type: application/json' -d '{}'
# → pending_approval again

curl -s -X POST localhost:3001/api/posts/ID/approve \
  -H 'Content-Type: application/json' \
  -d '{"actor":{"id":"local-dev","name":"Local"}}'
# → approved

curl -s localhost:3001/api/posts/ID/iterations
